# 本地剪辑实现参考

## 中间文件

为每个素材及修订版本建立独立工作目录。保留源转写、人工语义删减清单、时间线、字幕、章节定义和导出日志；不把某条视频的绝对路径、段号、标题、人物身份或删减时间固化进技能脚本。

建议转写结构为 `[{start, end, text, words:[{start,end,word,probability}]}]`。删减清单记录源时间与原因；先移除删除的词，再计算剩余词的输出时间。

## 静音与音频

`silencedetect=noise=-40dB:d=0.3` 可作为安静室内录音的起点，不是通用阈值。常见做法是压缩超过约 0.6 秒的冗余间隙，保留约 0.25–0.4 秒自然停顿；更长的演示/思考停顿应结合画面保留所需时间。按录音底噪调整阈值，低音量说话不是静音，呼吸声也不一定低于阈值。不要把每个静音区间压成零；保护语尾、辅音、必要换气和下一句起音。

沿共享保留区间裁剪原始音频，保留原声道和合理采样率。拼接边缘约 3–8 ms 淡入淡出；避免长淡化吞字。默认 `atempo=1.12` 保持音高；用户指定语速时从其指定。低频噪声确实存在时再做轻量高通；不要默认重降噪、强噪声门或背景音乐。

## 时间线工具

输入 JSON 示例，单位为源视频秒：

```json
{"duration":120,"fps":"30","speed":1.12,"cuts":[{"start":2.2,"end":3.1,"reason":"重复起句"},[20.5,21.2]]}
```

```text
python scripts/timeline.py plan.json --output timeline.json
```

输出包含按帧对齐的 cuts、keep、output_duration、source/output 对照区间、select_expr、setpts_expr 与 atempo_filter。

任意保留的源时间 t 映射为：所有保留区间中，t 之前的保留长度之和，再除以 speed。落在删除区间里的词应剔除，不能映射成零时长字幕留在画面中。

非恒定帧率素材先确定一致的工作帧率，或使用基于 PTS 的同步方案；不能直接套用按帧号的公式。实际 duration/fps 从探测结果读取。脚本需要 Python 3.9+ 标准库，无额外包。

FFmpeg 选择表达式：大量 `between(n,start,end)` 逐项左结合相加可能触发表达式递归深度问题，甚至报 `Cannot allocate memory`。使用脚本生成的平衡括号树，或分段渲染拼接。不要把这种错误直接判断为机器缺内存。

## 已确认的视觉参数

以下以 2160×1080 为参考，其他尺寸按宽高比例缩放，并依画面遮挡调整：

- 字幕：Microsoft YaHei，白色粗体、黑色描边，底部居中。2160×1080 可用 ASS `Alignment=2,MarginV=35` 起步，必须抽帧确认实际落点；字幕下沿与章节条上沿至少间隔画面高度的 4%。
- ASS 白字 `PrimaryColour=&H00FFFFFF`。字幕底框如需保留，按当前项目样式单独配置，不要把字幕框与底部章节灰板合并成通栏。
- 章节条：连续黑色底板，黑色不透明度 25%（ASS alpha `&HBF&`），左右边距约 36 px，y=1032 至 1080，底边与画布底边重合；底板高度约画面高的 4.44%，左右边距约画面宽的 1.67%。必须输出可见底板，不能依赖播放器原生进度条。
- 章节标题白色，参考字号约 21 px，简短概括该段内容，建议 2–6 个汉字。标题位于底板上层，保证对比度和完整可读。章节时间跨度很短时，不要按时长比例压缩标题可用宽度；将所有章节概括排入固定可读分区，确保整条大纲始终完整显示。
- 实时进度色 RGB `#F7C548`（ASS BGR `48C5F7`），透明度字节 `&H80&`，即 50% 不透明度。ASS alpha `00` 不透明、`FF` 全透明；检查通道与透明度，防止填充渲染成透明或颜色偏差。
- 绘制层级：灰色底板在最下，章节分隔与标题在其上，金色进度沿独立的最底边轨道推进。按讲解章节推进，已播放区域持续保留填充。章节短时仍保持固定标题区宽度；标题过长则精简概括或调整字号，不能挤压相邻标题。
- 更稳妥的布局是把底栏拆成“章节概括行 + 最底边进度线”：章节概括行横向预留均衡空间，进度线独立铺满可用宽度并按总时长推进。短章节仍显示完整标题；金色进度不能盖住文字，结尾章节不能越出画布边缘。

### 章节进度动画实现

- 不要默认依赖 ASS `\clip` + `\t` 动画推进进度：在已验证的渲染链路中，这种方式没有稳定显示动态填充。
- 稳定实现方式是把金色进度拆为窄小填充块，按时间逐块出现并持续到视频结尾。每块使用独立事件层；矢量矩形用 `\an7\pos(0,0)` 明确锚定到画布原点，底板同样明确定位。根据画布宽度调整块宽以保持推进平滑。
- 生成字幕或 ASS 后，在最终编码成片中抽查开头、章节中段、边界和结尾：确认灰色底板实际可见、进度持续推进、章节标题未被遮挡、底边与画布齐平、字幕留有安全间距。仅检查 ASS 文本不能证明渲染正确。

## 渲染与验证

从原始画面重新渲染修订版，不在已烧入字幕的视频上再次叠字幕。可用 H.264 + AAC、yuv420p、faststart；若 NVENC 可用则使用，失败后回退到本地可用编码器，不假定特定显卡始终存在。用源尺寸输出，不默认降成 1080p。

最后用 ffprobe 检查编码、分辨率、时长，用 `ffmpeg -v error -i final.mp4 -f null ...` 做解码检查（Windows 的空设备为 `NUL`）。抽查实际成片而非只检查 ASS 文件。字幕时长、章节开始、进度状态也需要检查。

ASR 的错误不能靠编码检测发现；音频剪口自然与否不能靠静音阈值或时长比较证明。输出准确说明做过的验证。
